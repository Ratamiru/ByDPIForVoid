# ByeDPI × TG Desktop

Маленький GUI на PySide6 для Linux (делался под Void), который управляет двумя локальными прокси:

| Что | Движок | Адрес | Куда прописать |
|---|---|---|---|
| Сайты (YouTube, Discord…) | [byedpi](https://github.com/hufrea/byedpi) | SOCKS5 `127.0.0.1:1080` | в браузер |
| Telegram | [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) | MTProto `127.0.0.1:1443` | в Telegram Desktop (кнопкой) |

Приложение само ничего не проксирует, оно только запускает и останавливает эти процессы, показывает их логи и состояние.

## Установка

```sh
./install.sh
byedpi-tg
```

Что делает `install.sh`:
1. ставит через xbps `git gcc make python3 curl xdg-utils`;
2. клонирует и собирает byedpi в `~/.local/share/byedpi-tg/byedpi`;
3. клонирует tg-ws-proxy рядом;
4. создаёт venv и ставит `PySide6-Essentials`, `httpx[http2]`, `certifi`, `cryptography`;
5. кладёт команду `~/.local/bin/byedpi-tg` и ярлык в меню приложений.

Повторный запуск `./install.sh` обновляет оба движка. Удаление: `./install.sh uninstall`.

> На **musl**-варианте Void колёса PySide6 из pip не встанут. Установщик это заметит и остановится.

## Как пользоваться

**Сайты**
1. Сначала нажми «Проверить DNS» (см. раздел ниже). Если DNS врёт, подбор стратегий бесполезен.
2. На вкладке «Подбор стратегий» нажми «Подобрать стратегию». Приложение по очереди запустит byedpi с каждой стратегией из списка на временном порту и проверит 12 адресов YouTube, включая видеосерверы `googlevideo.com`. Это займёт несколько минут.
3. Лучшая стратегия применится сама. Топ-8 попадут в выпадающий список «Стратегия», чтобы быстро переключаться, если лучшая начнёт сдавать.
4. Нажми «Запустить».
5. Подключи браузер одним из способов:
   - **Chromium/Brave**: кнопка «Браузер». Флаг `--proxy-server` работает, только если браузер ещё не открыт.
   - **Firefox**: Настройки → Параметры сети → Ручная настройка → SOCKS v5, `127.0.0.1`, `1080`. Обязательно включи галку «Отправлять DNS-запросы через прокси при использовании SOCKS v5».
   - Расширения вроде FoxyProxy / SwitchyOmega позволяют пускать через прокси только нужные сайты.

**Telegram**
1. Включи переключатель.
2. Нажми «Применить в Telegram»: откроется `tg://proxy?...`, Telegram предложит подключиться.
3. Если не открылось, жми «Копировать ссылку», отправь её себе в «Избранное» и нажми на неё.

Secret генерируется один раз и сохраняется, поэтому в Telegram прокси добавляется один раз.

**Не грузятся фото и видео в TG?** Впиши в «Доп. флаги» `--dc-ip 4:149.154.167.220`. Это совет из README tg-ws-proxy.

## Подбор стратегий: как это устроено

- **Список** — 60 стратегий из Android-приложения [ByeByeDPI](https://github.com/romanvht/ByeByeDPI) (файл `proxytest_strategies.list`). Кнопка «Обновить список» скачивает свежую версию с GitHub в `~/.config/byedpi-tg/strategies.list`. Обновляй, когда всё перестало работать.
- **`{sni}`** в стратегиях — поддельное имя сайта в фейковом ClientHello (флаг `-n`). Задаётся полем «Fake SNI», по умолчанию `google.com`, как в оригинале.
- **Как засчитывается сайт.** Ответ должен скачаться **целиком**. ТСПУ часто пропускает TLS-рукопожатие, а потом «замораживает» соединение после ~16 КБ. Простая проверка «сервер ответил кодом 200» такое пропускает, а эта нет.
- **Какие адреса проверяются** — ключ `test_sites` в конфиге. Таймаут на адрес — `test_timeout` (5 с).

Стратегии «протухают»: провайдеры обновляют фильтры волнами. Если YouTube отвалился, сначала попробуй следующие из выпадающего списка, потом заново запусти подбор, потом обнови список.

## Если виноват DNS

byedpi получает от браузера имя сайта и сам спрашивает его адрес у **системного** DNS. Если провайдер подменяет ответы для YouTube или не отдаёт их вовсе, не поможет ни одна стратегия. При этом все стратегии падают разом, на всех устройствах в этой сети.

Кнопка «Проверить DNS» спрашивает адреса `youtube.com`, `i.ytimg.com` и одного видеосервера у системы и, для сравнения, через DNS-over-HTTPS. Затем проверяет, что системные адреса лежат в сетях Google.

Если DNS подменён, на Void ставим локальный шифрованный DNS:

```sh
sudo xbps-install dnscrypt-proxy
sudo ln -s /etc/sv/dnscrypt-proxy /var/service/
```

По умолчанию он слушает `127.0.0.1:53`. Дальше надо направить систему на него, то есть в `/etc/resolv.conf` оставить только:

```
nameserver 127.0.0.1
```

Чтобы этот файл не перезаписывался:
- **dhcpcd**: добавь `nohook resolv.conf` в `/etc/dhcpcd.conf`;
- **NetworkManager**: создай `/etc/NetworkManager/conf.d/dns.conf` с содержимым `[main]` / `dns=none`.

Проверка: `getent hosts www.youtube.com` должен вернуть адрес вида `142.250.x.x` или `173.194.x.x`. Затем снова «Проверить DNS» в приложении.

## Трей

Закрытие окна сворачивает приложение в трей. Иконка двухцветная: левая половина отвечает за сайты, правая за Telegram. На niri трей показывает твой бар (waybar `tray`, Quickshell `SystemTray`). Если трея нет, закрытие окна просто выходит из приложения.

## Настройки

`~/.config/byedpi-tg/config.json`. Здесь всё, что есть в окне, плюс:
- `browser_cmd` — команда для кнопки «Браузер через прокси», `{port}` подставляется. Пример: `"brave-browser --proxy-server=socks5://127.0.0.1:{port}"`.
